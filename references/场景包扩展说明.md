# 场景包扩展说明（怎么加一个新场景）

核心（脚本 + 三档路由 + 台账 + 纪律）不动，新场景只加一份判据包。

## 加包步骤

1. 在本目录建 `判据包-<场景名>.md`，照 PM 包/通用包的格式写四段：
   - 静态项口径（哪几维脚本已出，达标线建议值）；
   - 裁判项（成对对冲：一个盯「要做到」，一个盯「别做过头」）；
   - 过度约束/冗余等对冲项的计数口径；
   - 未定死清单归口（这个场景里什么叫「没定死」）。
2. 判据必须写成「通过长这样 / 不通过长这样」，能被另一个人照着复核。
   不许写「要好、要有用」这类空话。
3. 在 SKILL.md 第六节的表里登记状态。
4. 若静态词表需要场景词（如生图的风格冲突词），在包内单列词表节，
   由调用方在跑脚本后人工/裁判补判——核心词表保持通用，不塞领域词。

## 例：AIGC 生图包（扩展位，未实现）判据会完全不同

- 参数完整性：尺寸/张数/风格/负面词给了没；
- 风格冲突：互相打架的风格词（「极简」又「繁复装饰」）；
- 参考图指定：要复刻什么、复刻到什么程度；
- 过度约束：把画面每个像素都描述死 → 出图僵硬；
- 未定死：「好看的构图」「合适的光影」= 生图里的模糊词。

成对对冲：**描述完整度 × 画面自由度**。——这页只是示意，真做包时按上面四段写全。

## 成对对冲的通用设计法（新包先过这三问）

1. 这一维单独优化会不会把另一维带坏？会 → 必须成对；
2. 这一维能被一句话糊弄过去吗？能 → 加反向维；
3. 人工看得出好坏吗？看不出 → 不该存在。
