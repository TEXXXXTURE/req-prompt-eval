# req-prompt-eval

给 PRD、需求文档和提示词打分的小工具。核心问题只有一个：**写没写死**。

人看需求要的是方向和逻辑；执行者（开发者、Agent）要的是细节——每个决策点
要么定死（有判据、有边界、有异常处理），要么显式标「未定死」。隐式留白就是
下游要靠猜的地方，也是返工的来源。这个工具把「定死程度」变成可以打出来、
可以跨版本对比的分。

## 它怎么打分

三档深度，按情况选，不一刀切：

- **轻档**：纯脚本数文本，零模型成本——模糊词密度、验收判据存在率、
  未定死挂牌、结构三项（完成定义/范围边界/质量门）。能程序判的绝不用模型。
- **中档**：加模型裁判判开放项（真细致还是画大饼、边界全不全）。
  成对对冲防刷分，裁判与被测不同源，分歧交人复核。裁判模型不写死，谁用谁接。
- **重档**：同任务多跑几遍（默认 3），看判据通过率和跨次一致率——
  飘的决策点就是没写死的点。

每次跑往分数台账追加一行。改一版跑一次，横着一比就知道改动有没有让它变好。

## 它不做什么

- **不给改写建议**——评测只给判断不给结果。一旦报告教你怎么写，指标就成了
  目标，会被凑分。
- **不给「满意度」打分**——可计数的是违例数、达标率、一致率。说不出哪里
  不对的「不满意」，按归因三去向进未定死清单。
- **不替谁定及格线**——只报分，阈值人拍板。

## 场景判据包

通用核心对所有提示词适用，场景判据按领域换。内置 PM/需求包与通用提示词包；
AIGC 生图等其他场景照 `references/场景包扩展说明.md` 加包即可，核心不动。

## 快速开始

```bash
python scripts/static_check.py examples/样例-需求片段.md
python scripts/static_check.py 你的文件.md --json --ledger 分数台账.jsonl --tag "本次改动"
```

需要 Python 3.8+，零依赖。中档/重档由调用方接自己的模型编排（SKILL.md 写了流程和纪律）。

## 目录

```
SKILL.md                     完整方法：三档路由、打分口径、铁律
scripts/static_check.py      静态检查器（轻档核心）
references/                  判据包（PM 需求 / 通用提示词 / 扩展说明 / 缺陷归因）
templates/                   评分卡、未定死清单模板
examples/                    试跑样例
```
